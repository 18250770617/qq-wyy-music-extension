## 歌单卡顿诊断

- 只读基线 `system.ping` 为约 121ms；旧单通道中先读取 80 首歌单再发 ping，歌单和排队 ping 都在约 3023ms 返回，延迟放大约 25 倍。
- 同一官方 CLI 读取 80 首总耗时约 2731ms，但进程 CPU 仅约 125ms，说明主要瓶颈是 CLI 初始化与 I/O 等待，而不是持续 CPU 饱和。
- mpv 音频解码运行在独立进程，因此该数据能直接证明旧实现会冻结频谱、进度和控制反馈，不能单独证明 PCM 声音发生断流；V0.6.1 已通过三通道隔离消除这条已证实的队头阻塞路径。
